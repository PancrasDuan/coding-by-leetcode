速查

一张纸就能回忆的压缩版

题面要找所有 nums[i] + nums[j] + nums[k] == 0 的三元组。本页和 Java 统一用下标 i、left、right（题面的 j、k 就是 left、right；文中「左指针」「右指针」也指这两个下标）。来源：LeetCode 15 官方题面。约束 n <= 3000，主路径必须是 O(n²)。

  1. 排序，让枚举顺序固定为 nums[i] ≤ nums[left] ≤ nums[right]。
  2. 从左到右固定 i。若 nums[i] == nums[i-1]，跳过。
  3. left = i + 1，right = n - 1，在 i 右侧做两数之和，目标和是 -nums[i]。
  4. 按和的大小移动指针；找到一组后两边都收缩，并跳过相同的 nums[left]、nums[right]。
sum < 0left++，需要更大的数。
sum = 0先记下当前三元组，再 left++ 且 right--，然后跳相同值。
sum > 0right--，需要更小的数。

两处跳过

  • 第一个数：i > 0 且值与前一个相同，则整轮不跑。
  • left / right：找到一组之后，跳过相邻相同值。反例是 [-2,0,0,2,2]，不是 [0,0,0]。

固定 i 后，nums[left] 增大则满足条件的 nums[right] 只能变小，所以后两个下标是并列的双指针。LeetCode 官方题解。排序 O(n log n)，每轮左右指针均摊 O(n)，总时间 O(n²)。

Wikipedia 3SUM 的二次算法假设元素互异，找到后左右指针直接一起动即可。LeetCode 允许重复值，所以多了这两处跳过。

02 · Primary source

三重循环过不了，是约束决定的

题面约束是 3 <= nums.length <= 3000。O(n³) 大约 2.7×10¹⁰ 次，面试实现里直接淘汰。经典 3SUM 在维基百科的二次算法里，也是先排序，再固定 i，用 left 和 right 找 nums[left] + nums[right] == -nums[i]。

LeetCode 官方题解补了刷题时真正难的那一层：不但要找到，还不能重复。排序后只枚举 nums[i] ≤ nums[left] ≤ nums[right]；相邻相同值跳过。

03 · Movement

只记三条移动规则

排序后，i 从左往右钉住第一个数，left = i + 1，right 从最右端回来。数组有序：left 右移会让和变大，right 左移会让和变小。

和 < 0left 右移，换一个更大的数。
和 = 0记下三元组，left / right 都收缩，并跳过相同值。
和 > 0right 左移，换一个更小的数。

Part 2

命中之后，还要跳过相同的左右值

原来的第二课。官方例子藏不住左右重复，要用 [-2,0,0,2,2]。

目标

这一段要能口述的东西

[-2,0,0,2,2] 第一次记下 [-2,0,2] 之后，如果只做 left++ 和 right--，为什么还会再记一次。正确顺序是：先记下当前三元组，再移动，再用 while 跳过相同值。

01 · 为什么官方三例不够

官方例子测不出左右重复

[-1,0,1,2,-1,-4] 命中后左右下一个值刚好都变了，所以只写 left++ / right-- 也能过。[0,0,0] 三个 0 用完指针就相遇，同样测不出来。真正会爆的是左右两侧都有重复、中间还能再夹一次的数组，比如 [-2,0,0,2,2]。

04 · 规则

去重有两处，不是一处

跳过 i还没开始夹逼，相邻第一个数相同就整轮不跑。
命中后跳 left / right已经记下了一组，左右各走一步，若值没变就继续走。
不要提前结束跳的是相同的 nums[left]、nums[right]，不是换下一个 i。

sum == 0 的顺序必须是：先记下当前三元组，再移动，再用 while (left < right && …) 跳过相同值。先移动再决定记不记，会丢掉官方示例 1 的 [-1,-1,2]。
