一整座岛，怎样只数一次？

学习目标：先理解状态变化，再独立用 Java 实现岛屿计数。当前已完成原地标记的递归解法。

题意 · 手推 · 递归任务 · 自测 · 速查 · 子集复习

1. 数的是连成片的陆地

按原题，只考虑上下左右相邻，斜角不相连。

1 1 0
0 1 0
1 0 1

左上三个 1 连成一座岛；左下和右下各是一座，一共 3 座。陆地格子数量是 5，岛屿数量是 3。

2. 找到新岛后，先认领整座岛

从上到下、从左到右扫描。你的实现把访问过的陆地从字符 1 改成字符 0，以此代替独立的 visited 数组。下面用 ● 表示“已经标记的陆地”，代码中它实际已经变成 0。

初始             从 (0,0) 搜索完后
1 1 0            ● ● 0
0 1 0            0 ● 0
1 0 1            1 0 1
计数 0           计数 1

坐标从 0 开始。搜索从 (0,0) 走到 (0,1)，再走到 (1,1)，把相连陆地全部标记。外层继续扫描时，(0,1) 和 (1,1) 都跳过。直到 (2,0) 才发现新岛，计数变成 2；(2,2) 让计数变成 3。

外层负责找新岛并计数；内层搜索负责标记整座岛。搜索走到另一块陆地时，不再加岛屿计数。

这对应连通分量算法：每次从未访问的节点出发，覆盖它所在的整个连通分量。

3. 一次递归负责什么？

把 dfs(r,c) 理解成：“从这个坐标出发，把能通过陆地走到的格子都标记。”DFS 就是先沿一条路深入，走不通后返回，再继续其他方向。

遇到越界、水或已经访问的格子，就结束当前调用。遇到新陆地，先标记自己，再分别探索上下左右。必须先标记，否则相邻的两个格子可能互相走回去。

返回只结束当前调用，调用它的那一层还会继续检查剩下的方向。

与子集练习对比：返回时要恢复成 1 吗？

不撤销。子集的 path 表示当前选择，需要恢复后探索其他选择；本题把陆地改成 0，表示它已被统计，整个扫描过程都保留这个事实。

③ 如果递归返回时清除访问标记，会发生什么？

核对反馈

同一块陆地会再次变成未访问，后续可能重复搜索、重复计数；多条连通路径还可能导致大量重复探索。

复习速查：你的实现

外层扫描：遇到 '1'，计数加一，再调用 dfs。内层搜索：先检查越界或 '0'，符合就返回；否则把当前格子改成 '0'，依次探索上、下、左、右。

四邻坐标：(r−1,c)、(r+1,c)、(r,c−1)、(r,c+1)。先判断边界再访问数组，Java 的 || 短路求值保证越界时不读取该格子。

原地标记会修改输入；同一个网格被完整搜索后，再次调用会得到 0。每个测试应使用独立输入。

m 行 n 列：扫描 mn 格，每格最多有效访问一次，检查四个方向，时间 O(mn)。没有独立 visited 数组，但最坏递归深度为 mn，因此辅助空间为 O(mn)。

已验证与限制

Java 21 本地验证：官方样例输出 1、3；全部 4096 种 3×4 二值网格与独立 BFS 对照一致。300×300 全陆地在本地 JVM 出现 StackOverflowError：计数逻辑正确，但深递归受栈容量限制。若要稳妥处理大网格，可改成显式栈 DFS 或队列 BFS；当前归档保留你完成的递归实现。
