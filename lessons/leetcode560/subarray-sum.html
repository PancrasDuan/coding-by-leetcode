和为 K 的子数组

从连续区间到两个前缀的差，再从查找变成计数。

约 8 分钟目标：独立推导并实现2026年10月2日归档LeetCode 已通过
推导逐步演示动手写速查卡三数之和复习

先确认我们在数什么

nums = [1,2,3]，k = 3。符合条件的是下标 0..1 的 [1,2]，以及下标 2..2 的 [3]，答案为 2。子数组必须连续且非空；同样的数值出现在不同位置，算不同的子数组。题意与样例来源。

最直接的方法：固定左端点，向右累加，每次和等于 k 就加一。累计求和的双层枚举是 O(n²)；我们要优化反复寻找左端点的过程。

题目允许负数。对于 [3,-1]，k=2，先看到 3 就因“和太大”丢掉它，会漏掉整个区间。因此不能直接套用“和大就缩、和小就扩”的滑窗规则。元素范围来源。

减掉前面，剩下中间

定义 P[t] 为前 t 个元素的和，因此 P[0]=0。它标记的是元素之间的边界。

nums = [1, 2, 3]
P = [0, 1, 3, 6]
区间 nums[l..r] 的和 = P[r+1] − P[l]。

例如最后一个元素 [3]：前 3 个元素的和 6，减去前 2 个元素的和 3，得到 3。这就是两个前缀相减后只剩中间区间。

当我们走到右端点 r，当前和记为 sum = P[r+1]：

sum − P[l] = k
↓
P[l] = sum − k

于是问题变成：之前的前缀和里，有多少个等于 sum-k？每个匹配的边界 l，都对应一个以 r 为右端点的合法子数组。这一推导与 LeetCode 官方提示给出的“区间差值 + 和的出现次数”方向一致。

当前 sum=6、k=3，应当查哪个历史前缀和？

哈希表记的是出现次数

freq.get(s) 表示历史前缀和 s 出现过几次。先预测本步会找到几个区间，再点击“下一步”。从普通样例切换到重复前缀和，观察为什么不能只用 Set。

查询时的 freq

登记本步 sum 后

在 [1,-1,1]，k=1 中，处理最后一个 1 时，历史前缀和 0 出现过两次：边界 0 和边界 2。因此本步新增 [1,-1,1] 与最后一个 [1]，不是只加 1。连同第一个 [1]，总计 3 个。

两个实现细节都来自“边界”

为什么先放 freq[0]=1？

读元素前就存在边界 P[0]=0。对于 [3]，k=3，sum-k=0；匹配它，才能数到从数组开头起的区间。它不是把空数组算进答案，而是提供一个合法左边界。

为什么先查，再登记？

查询时，表里只能有当前右边界之前的边界。若先登记当前 sum，在 k=0 时，会匹配当前边界自身，错误计入长度为 0 的区间。例如 [1]，k=0 应当返回 0。

每步更新 sum 后，接下来的顺序应当是什么？

复习时，先独立重写一次

打开 Leetcode560.java，复习时先凭记忆重写 subarraySum，再与完成的实现核对。变量只需要 sum、count 与 Map<Integer,Integer> freq。不需要真的保存整个 P 数组。

初始化 sum、count 和 freq
登记初始边界：freq[0] = 1
对于 nums 中的每个 x：
    ① 把 x 加到 sum
    ② count 增加「历史前缀和 ______ 的次数」
    ③ 把当前 ______ 的出现次数加一
返回 count
填完再核对两个空

第一个是 sum-k，第二个是 sum。Java 取频次可用 freq.getOrDefault(key, 0)，写回用 freq.put(key, value)。

每步新增的区间都有唯一右端点；同一步中不同历史边界代表不同左端点，所以不会重复统计。同一个前缀和值可以对应多个边界，频次正好保存这个数量。

HashMap 操作平均为 O(1)，遍历一次，平均时间 O(n)，额外空间 O(n)。题目最多 20000 个元素，因此子数组总数至多 200010000，Java 的 int 足够保存答案。

复习速查

前缀和 + 历史频次

适用：统计连续非空区间的和恰好为 k 的个数，允许负数。返回完整推导 · 返回逐步演示

课件中的 freq 对应你的代码变量 map；课件中的 count 对应 res，含义相同。

统一术语

符号含义
P[t]前 t 个元素的和；P[0]=0
sum处理 nums[r] 后的 P[r+1]
freq[s]查询前，历史前缀和 s 出现的次数
count已统计的合法子数组个数
区间和 = P[r+1] − P[l]
区间和为 k ⇔ 历史 P[l] = sum − k

记住流程，不背代码

初始：sum=0，count=0，freq[0]=1。

  1. 累加当前元素到 sum。
  2. count 加上 freq[sum-k]，不存在就加 0。
  3. freq[sum] 加一。

平均时间 O(n)，额外空间 O(n)。

三个边界理由

  • 存次数：同一个前缀和值可以对应多个左边界。
  • 初始 0：代表读取元素前的边界，覆盖从下标 0 开始的区间。
  • 先查后记：避免 k=0 时计入当前边界自身，即空区间。

自测：[1,-1,1]，k=1 → 3；[0,0]，k=0 → 3；[1]，k=0 → 0。

public int subarraySum(int[] nums, int k) {

    Map<Integer, Integer> map = new HashMap<>();
    map.put(0, 1);
    int res = 0;
    int sum = 0;
    for (int i = 0; i < nums.length; i++) {
        sum += nums[i];
        if (map.containsKey(sum - k)) {
            res += map.get(sum - k);
        }
        map.put(sum, map.getOrDefault(sum, 0) + 1);
    }

    return res;
}
